一、复现
--------
步骤：打开「实时日志」→ 点 ③ 任一行（带 traceId 或聚合行）拉起 ⑤ → 观察左侧 ② 过滤栏。

修复前实测（1440×800，探针把内联 overflow 还原为 visible 复现旧形态）：
  .ev-rail        y=234.8..526.5（高 292）
  .ev-rail .sev   y=502.8..561.8  ⇒ 从栏底溢出 35.3px
  .ev-rail .foot  y=561.8..595.8  ⇒ 从栏底溢出 69.3px
  ⑤ 标题带        y=527.5..561.5
  ⇒ 严重度四枚（信息/防护/警告/错误）与「全部打开 / 清筛选」直接画在 ⑤ 的标题和链路上，
     两组文字互相叠印。截图 3a4h-drawer-rail-before.png。

窗口高度越小越严重：1366×768 时栏可视高 242、内容 361（溢出 119）；
1280×720 时可视高 188、内容 361（溢出 173）。


二、根因
--------
1) ⑤ 抽屉 `max-height: 42%` 吃掉 `.ev-frame` 的高度，`.ev-body`（唯一伸缩行）只剩一半；
   1440×900 时栏高 392、内容 361（恰好放得下），800 时栏高 292 ⇒ 放不下。
2) ② 栏里「口径 / 严重度 / 全部打开」都是 `flex: 0 0 auto`（按判定压不下去）；
   `.rows` 已按设计缩到 0 附近，剩余固定块仍超出栏高。
3) `.ev-rail` 的 `overflow` 默认 `visible` ⇒ flex 子块直接从栏底画出去，
   与下方 ⑤ 的标题 / 链路文字叠印（不是 z-index 问题，是内容越界绘制）。


三、修复（EventLog.vue · 只有 CSS）
----------------------------------
1) `.ev-rail` 增加 `overflow-y: auto; overflow-x: hidden;`
   ⇒ 先保证内容**不出界**；空间不足时整栏可滚动，栏底控件仍够得着。
   正常高度（抽屉收起 / 900 高）内容不超出，不出现滚动条，原布局不变。
2) `.ev-rail` 纳入既有 7px 淡色滚动条规则（宽度 / 轨道 / 滑块 / hover / corner），
   避免兜底滚动条退回 Chromium 默认 15px、比行清单还抢眼。
未改动模板、数据链与 ⑤ 的任何逻辑。
