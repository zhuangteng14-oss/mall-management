── ⑧ 读法（这一条要读准） ──────────────────────────────────────────────────
· ① ② ⇒ user 侧那条 UPDATE **走 PRIMARY**：key=PRIMARY / key_len=80 / rows=1 / filtered=100。
  （type 显示 range 而不是 const 属正常：**DML 的修改目标**在计划里一律记 range，即便等值是唯一键。）
· ⑦ ⇒ 三份 dump 里，**user 侧每一段 RECORD LOCKS 都只有 1 条 Record lock**（持有 1 条、
  等待也是 1 条；从未出现 user 侧多行锁）。而 '49 row lock(s)' 只出现在基线那一份，
  且**全部在 goods 侧**（relist 那条无索引可走的 UPDATE 全表扫描）。
· 审计侧事务的 4 row lock(s) = user 侧 1 条 + goods 侧 3 条（它自己那侧也没有批量行锁）。
⇒ 结论：该侧本来就只锁 1 行 ⇒ user.merchantid 索引**不必加**。
