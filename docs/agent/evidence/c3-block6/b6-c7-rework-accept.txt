    Id=115（实名评价） created_at 2026-10-13 05:25:11 · updated_at 04:46:44
    Id=116（商家回复） created_at 2026-10-13 05:35:11 · updated_at 03:55:11
    Id=117（顾客回复） created_at 2026-10-13 04:55:11 · updated_at 03:55:11

  **意图的目标值**（= 种子落库时刻 03:55:11 − 各自的 `minutesAgo`：120 / 90 / 100 / 60）：
    Id=114 → 01:55:11 · Id=115 → 02:25:11 · Id=116 → 02:35:11 · Id=117 → 02:55:11

  **为什么必须回拨**：符号翻转把**意图的时间先后**翻了过来 ——
    · 页面上「匿名评价（05:55）」比「实名评价（05:25）」**更晚**；
    · 「顾客回复（04:55）」比「商家回复（05:35）」**更早**。
  根因：MySQL 服务端时钟是 UTC，宿主是 CST(+8)，`NOW()` 读数比宿主低 8 小时；
  种子脚本里 `NOW() - INTERVAL ? MINUTE` 的 `?` 被写成负数 ⇒ 负负得正 ⇒ 落到未来。

  **执行的 UPDATE（一条语句，显式字面量 —— 不再用相对时刻，免得同一个坑再踩）**：
    UPDATE comment SET created_at = CASE Id
      WHEN 114 THEN '2026-10-13 01:55:11' WHEN 115 THEN '2026-10-13 02:25:11'
      WHEN 116 THEN '2026-10-13 02:35:11' WHEN 117 THEN '2026-10-13 02:55:11'
      ELSE created_at END,
      updated_at = updated_at                    -- 显式赋当前值 = 抑制 ON UPDATE CURRENT_TIMESTAMP
     WHERE Id IN (114,115,116,117);
    ⇒ `-- affected: 4`
