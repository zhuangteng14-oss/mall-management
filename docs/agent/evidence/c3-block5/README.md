## 2026-10-11 手验五件 —— ① / ② 的后端实测

**①「券没过期却领不了」的结论（不是猜的）**：库时钟 = **UTC**（`@@system_time_zone='UTC'`，
实测 `NOW()` = `2026-10-11 14:20:15`），而用户建券时填的「22:01 起」被**当成本地墙钟原样入库**
⇒ 库内是 `2026-10-11 22:01:00` UTC = 本地次日 06:01 ⇒ **真因是「还没开始」**，不是「已过期」。
旧话术把两个原因合并成「已过期或已领完」，把人指去了错方向。根因修在**建券表单的时区换算**
（`MarketingPage.vue` 照 `AuditPage.vue` 既定口径：显示 `toLocal`、输入 `toSqlTime`），
**同族第二落点**（`CouponService.isExpired` 用 JVM 时钟，比库时钟早 8 小时）一并收掉。

**② 话术拆分 —— 对着跑着的后端实测（POST `/marketing/coupon/claim`）**：

| 券的状态 | 后端 `msg` | 前端拼出来 |
|---|---|---|
| `active`，`StartAt` 未到 | `该券还未开始` | `领取失败：该券还未开始` |
| `stopped` | `该券已停止发放` | `领取失败：该券已停止发放` |
| 不存在 | `券不存在` | `领取失败：券不存在` |

`msg` **不带**「领取失败：」前缀（前缀归调用方拼），也不再合并原因 —— 全仓 `grep '已过期或已领完'`
只剩三处**负面引用**（注释里写「不再这么说」）。

> ⚠️ **旧券不要拿来验 ①**：`CPABQL05486349` / `CPSFNX60435405` 是**按旧口径**建的
> （StartAt 被当成 UTC 存）⇒ 新列表会把它们显示成**次日 06:01 / 06:10**，仍然「还没开始」。
> 手验请**新建**一张券。
