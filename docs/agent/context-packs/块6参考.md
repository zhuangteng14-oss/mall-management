## 一、表设计（6 张新表）

### 1. `comment`（评论主表）

```sql
CREATE TABLE IF NOT EXISTS `comment` (
  `Id`              bigint NOT NULL AUTO_INCREMENT,
  `TargetType`      varchar(16) NOT NULL COMMENT 'goods / user',
  `TargetId`        varchar(50) NOT NULL COMMENT '对象 ID',
  `ParentId`        bigint DEFAULT NULL COMMENT 'NULL=顶层；!=NULL=回复（顶层评论 Id）',
  `ReplyToId`       bigint DEFAULT NULL COMMENT '回复的回复：被回复的回复 Id；普通回复=NULL',
  `Kind`            varchar(16) NOT NULL DEFAULT 'review' COMMENT 'review / question / answer',
  `AuthorId`        varchar(40) NOT NULL COMMENT '作者账号 login.UserName',
  `AuthorRole`      tinyint NOT NULL COMMENT '1=用户 / 2=商家',
  `IsAnonymous`     tinyint(1) NOT NULL DEFAULT 0 COMMENT '0=实名 / 1=匿名',
  `Rating`          tinyint NOT NULL DEFAULT 5 COMMENT '1-5；匿名=5；问答=0',
  `Content`         varchar(1000) NOT NULL COMMENT '正文（敏感词已屏蔽 ***）',
  `Status`          varchar(16) NOT NULL DEFAULT 'normal' COMMENT 'normal / deleted',
  `IsSolved`        tinyint(1) NOT NULL DEFAULT 0 COMMENT '问答：0 未解决 / 1 已解决',
  `AcceptedReplyId` bigint DEFAULT NULL COMMENT '问答：被采纳的回复 Id',
  `IsMerchantFirst` tinyint(1) NOT NULL DEFAULT 0 COMMENT '商家首次回复置顶标记',
  `ProductCode`     varchar(40) DEFAULT NULL COMMENT '购买型号（评论时选，来自历史订单）',
  `LikeCount`       int NOT NULL DEFAULT 0 COMMENT '点赞数冗余',
  `DislikeCount`    int NOT NULL DEFAULT 0 COMMENT '踩数冗余',
  `created_at`      datetime NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `updated_at`      datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`Id`),
  KEY `idx_comment_target` (`TargetType`,`TargetId`,`created_at`),
  KEY `idx_comment_parent` (`ParentId`,`created_at`),
  KEY `idx_comment_author` (`AuthorId`,`created_at`),
  KEY `idx_comment_kind`   (`Kind`,`TargetType`,`TargetId`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='统一评论表（块 6）';
```

**结构说明：**
- 顶层评论：`ParentId = NULL`
- 回复：`ParentId = 顶层评论 Id`
- 回复的回复：`ParentId` 仍是顶层 Id，`ReplyToId` = 被回复的回复 Id
- **两层扁平**（同一 ParentId 下所有回复平级）


## 四、业务规则

### 4.1 评论区

**展示元素（照 B 站风格精简）：**
```
[头像] 用户名（匿名=首字*****）    时间
正文（敏感词 ***）
[图片附件]（待审"审核中"/被拒"图片违规已删除"）
购买型号：降噪款
─────────────────────
👍 104   👎 2   💬 回复
─────────────────────
  回复区（缩进）
  ├ 用户A：内容                      👍 5  👎 0  💬
  ├ 用户B 回复 @用户A：内容           👍 2  👎 0  💬
  └ 共 N 条回复  [展开]
```

**发评论资格**：
- 必须买过该商品 + `ReceiveIf=1`（已结单）
- 未购买 → 评论按钮 disabled + tooltip "购买后可评价"
- 评论时选"对应商品"（从历史订单里选，`ProductCode` 落库）

**评论规则**：
- 一发不可改
- 作者可删（连带回复一起删）
- 回复被删只删那条

**唯一性**：一商品一用户只能评一条

**匿名**：
- 可选
- 匿名 → `Rating` 强制 5 + 显示 `首字*****`
- 实名 → 可选 1-5 星

**回复权限**：任何登录用户
**商家首次回复** → `IsMerchantFirst=1` → 置顶
**商家后续回复** → 混排

**@ 自动**：
- 顶层评论 → @ 该商品商家
- 回复顶层 → @ 顶层作者
- 回复回复 → @ 被回复人

**点赞/踩**：顶层评论和回复都适用；每条 comment 行下都有 `👍 N / 👎 N / 💬 回复` 三入口

**排序**：
- 默认时间倒序（晚的在最上）
- 可切按热度（点赞数）

**列表**：限高 + 内部滚动

### 4.2 问答区

- 谁都能提问（不限购买）
- 发问人不允许匿名（实名）
- 回复人只能匿名（商家除外——商家实名）
- **布局**：左圆比例图（已解决/未解决）+ 右问答列表
- **采纳**：提问者选一个答案 → `AcceptedReplyId` + `IsSolved=1` + 置顶
- 采纳后不可改
- **删除**：提问者不能删；商家可提删 → 管理端裁判
- **30 分钟未解决** → Job 报管理端
- 问答区跨型号共享（同商品同一批）

### 4.3 图片审核流

```
1. 用户提交评论 + 图 → 评论立即落库、图 status='pending'
2. 前端展示评论：文字可见、图显"审核中"
3. 管理端 → 内容治理 → "待审图片"
4. 通过 → 'approved' → 前端正常显示
5. 不合规 → 'rejected' + 删仓库文件 + 前端显"图片违规已删除"
```

**存储位置**：`static/img/comment/`

### 4.4 举报规则

- 可举报：评论 / 回复 / 商品 / 用户
- 举报人：任何登录用户 / 商家
- 理由：辱骂 / 广告 / 违法 / 其他
  - 其他 → 下方 100 字文本框
- 不能举报自己
- 同内容不能二次举报（DB UNIQUE）
- 处理：管理员通过 → 删内容 + 通知原内容作者（理由）
- 驳回后可再举报（需重选/填理由）
- **警告累计**：`user.WarnCount +1`；3 次 → 自动封号
  - 封禁接口复用"用户与商家治理"的封禁
  - 解封 = 管理员去用户与商家治理手动解
- 举报匿名（管理端可见全名 + 类型）

### 4.5 敏感词

- 管理端维护（预置 10 个）
- 命中但占比 < 40% → 屏蔽 `***` + 落库
- 命中占比 ≥ 40% → 拒收
- 不提示用户（发出后自己看 `***`）
- 加词后扫老评论
