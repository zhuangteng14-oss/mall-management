【1.2 两种编排模式】

模式一 · 固定一键（预置 8 场景，各一键）

模式二 · 自定义编排（8 权重滑条 + 总并发 + 持续时间）
  ┌──────────────────────────────────────────┐
  │ ☑ 秒杀抢购      权重 [====----] 40%      │
  │ ☑ 订单并发      权重 [===-----] 30%      │
  │ ☑ 重复提交      权重 [==------] 20%      │
  │ ☐ 超时不付款    权重 [--------]  0%      │
  │ ☐ 缓存冷启      权重 [--------]  0%      │
  │ ☐ Redis 断开    权重 [--------]  0%      │
  │ ☐ 封禁用户攻击  权重 [--------]  0%      │
  │ ☐ 敏感词攻击    权重 [--------]  0%      │
  ├──────────────────────────────────────────┤
  │ 总并发数 [100]  持续 [60] 秒              │
  │              [开始]                       │
  └──────────────────────────────────────────┘
  用途：答辩互动 —— "现在把秒杀调到 80%，看系统扛不扛得住"。

【1.5 演练记录 —— C7：新建表 drill_record】

表结构（新表，长文本存，后端拆接给前端）：
  · Id              bigint PK AUTO_INCREMENT
  · OperatorId      varchar(40)   —— 谁跑的（业务号）
  · OperatorRole    tinyint       —— 1/2/3
  · Name            varchar(64)   —— 场景名（或「自定义」）
  · Scenario        varchar(500)  —— 场景配置 JSON（8 场景 + 权重）
  · TotalRequests   int           —— 总请求数
  · BlockedRequests int           —— 被防护拦下数
  · FailedRequests  int           —— 真失败数（5xx 等）
  · DurationMs      bigint        —— 跑了多久
  · Result          mediumtext    —— 长文本结果（后端拆接给前端）
  · created_at      datetime
  · updated_at      datetime

⚠️ 后端拆接：Result 长文本，后端解析后分内容给前端用于显示。
   不是为了展示原始长文本，是为了「分字段显示」。
