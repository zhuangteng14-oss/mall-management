# B 笔 v5 · 字体探索报告

> **范围边界（先声明，免得误读）**：本笔**只给设计稿阶段的结论**。仓库 `src/assets/fonts/`
> 里**不放**任何新字体文件；10 份稿用项目外的本地 fontsource 试效果，
> 产品侧沿 `--font-display` 链**自动降级**回 Noto Serif SC。自托管留到「落 Vue」那一步，
> 那时按本报告 §七 的方案只装定下来的那一档。
>
> **数据口径**：体积一律用 `ls -l` 的**字节求和**（`/1048576` → MiB），不是 `du` 的块口径
> —— 两者会差 10%+（例：文楷 `du` 报 37M，实际字节 32.6 MiB）。

---

## 一、问题与边界

用户 v5 收尾的原话：

> 「字体方向探索 —— 不必局限于宋体 / 微软雅黑；可以用更柔美的字体。」

并给了四条边界（下面逐条对照本笔的做法）：

| 用户给的边界 | 本笔做法 |
|---|---|
| 设计稿阶段可以用 CDN / 本地 fontsource 试 | 用项目外 `美化/node_modules` 的本地 fontsource（**不用 CDN**，离线可复现） |
| **不能全塞进仓库**（中文全字库每族 ~5MB，试 5-6 种 = +30MB） | 仓库**零新增**字体文件；设计稿只加 `<link>` |
| 选 2 种定下来（一款正文 + 一款标题，或一款全文） | **只换 1 处**：`--font-display`（标题）。正文族 `--font` **不动** —— 理由见 §四 |
| 落 Vue 时自托管、那时只装定下来的几种 | §七 给了确切体积与档位 |

⚠️ 用户简报里「中文全字库每族 **~5MB**」这个估算是**偏低**的，实测差 2 倍（§三）。

---

## 二、第一道闸：可商用授权（先砍掉一半候选）

自托管 = **再分发**字体文件。所以判据不是「免费商用」，而是**「许可协议允不允许再分发」**。

| 候选 | 许可 | 能不能自托管 | 结论 |
|---|---|---|---|
| 思源 / Noto 系（Source Serif 4、Noto Serif SC…） | SIL OFL 1.1 | ✅ | 可用 |
| 霞鹜系（LXGW WenKai GB、WenKai Screen、Neo Xi Hei…） | SIL OFL 1.1 | ✅ | 可用 |
| 975 圆体 SC | SIL OFL 1.1 | ✅ | 可用 |
| 猫啃珠圆体 | ⚠️ `package.json` 的 `license` 字段是 **`unknown`**，包内**无 LICENSE 文件** | ❌ 判据不成立 | **不采用**（不是嫌它难看，是**没法举证**） |
| HarmonyOS Sans / MiSans / vivo Sans / OPPO Sans | 免费商用，但**明令禁止再分发** | ❌ | **排除** |

⇒ 「免费商用」和「可自托管」是两件事。这一闸把 HarmonyOS Sans / MiSans / vivo Sans 这类
**观感最接近需求**的候选全挡住了 —— 它们恰恰是中文界面里最常见的「柔」的来源。

> 补充一句给将来落地用：`cn-fontsource-*` 那几个包**包内不带 LICENSE 全文**，
> 只在 `package.json` 里写 `license` 字段。自托管时要把上游的 OFL 文本一并放进仓库，
> 不能只留字段。

## 三、第二道闸：体积（实测，不是估算）

| 包（字体） | 字重档 | woff2 片数 | 体积（字节口径） | 授权 |
|---|---|---|---|---|
| `@free-fonts/lxgw-wenkai-gb`（**霞鹜文楷 GB**）| **300 / 400 / 500** | 1473（491 × 3）| **32.6 MiB**（300:11.4 / 400:10.4 / 500:10.8）| OFL 1.1 |
| `cn-fontsource-975-maru-sc-regular`（975 圆体 SC）| 400 | 609 | 8.3 MiB | OFL 1.1 |
| `cn-fontsource-maoken-zhuyuan-ti-regular`（猫啃珠圆体）| 400 | 158 | 2.7 MiB | ⚠️ unknown |
| `cn-fontsource-lxgw-neo-xi-hei-regular`（霞鹜新晰黑）| 400 | 199 | **2.3 MiB** | OFL 1.1 |
| `@fontsource-variable/source-serif-4`（拉丁 only）| 可变 wght | 36 | 2.1 MiB | OFL 1.1 |
| （**仓库现有**）`noto.css` + `mono.css` | 可变 wght | 208 | **10.1 MiB** | OFL 1.1 |

### 3.1 用户的「~5MB/族」偏低了

最柔的那款（文楷）**单档就是 10.4–11.4 MiB**，三档 32.6 MiB —— 是用户估算的 **2～6 倍**。
「试 5-6 种 = +30MB」这个担心是对的，只是**一种就能到 32MB**（如果三档全装）。

### 3.2 一个反直觉的结论：**柔美是贵的**

- 霞鹜新晰黑（黑体、中性）**2.3 MiB**
- 霞鹜文楷（楷体、柔美）**10.8 MiB / 档**

同样的字表（GB 常用字），**楷体是黑体的 4.7 倍**。原因不神秘：楷体的笔画有粗细变化与顿挫的
点画，每个字形的轮廓点比等线黑体多得多 ⇒ 压缩后仍然大。

⇒ 这条改变了取舍的算法：**不能拿「体积小」去挑柔美候选**，柔美候选本来就都贵；
反过来，**最便宜的那款（新晰黑）恰恰是最不柔的那款**。

### 3.3 字重：柔美候选里**只有一款**有真三档

| 候选 | 字重 | 后果 |
|---|---|---|
| 霞鹜文楷 GB | 300 / 400 / 500（**真字重**） | 要调重有得调 |
| 新晰黑 / 975 圆体 / 珠圆体 | **单档 400** | 想要 500 只能**伪粗**（浏览器合成加粗，笔画会糊） |

⚠️ 这一条影响的不只是「将来想不想调」，它**直接决定了 §五 那个连带决定**。

### 3.4 数字等宽（顺手拆掉一处隐患）

实测：文楷 / 新晰黑 / 975 圆体 / Source Serif 4 的**数字天然等宽**；
**Noto Serif SC 是全批唯一需要 `tabular-nums` 才对齐的族**。换掉它等于顺手拆掉一处隐患
（价格列、小计列的对齐不再依赖那行声明）。这一条写进了 `ProductPage.html` 的价格段注释。

---

## 四、第三道闸：可读性 —— 它决定的是「换哪一处」，不是「换哪一款」

楷体在 **12–15px** 上笔画易粘（横画之间只有 1px 空隙，屏幕渲染会糊成一团），
阅读成本高于观感收益。

⇒ 所以本笔的结论不是「换一款字体」，而是「**换一处字体**」：

```
--font         （正文 / 信息层：规格、订单号、表格小字）  → 不动，仍 Noto Sans SC
--font-display （标题 / 大字：页标题、商品名、价格、小计） → 换成楷体
```

这**不违背** tokens.css 原有的房规「黑体正文 + 衬线标题是最有效的一档配对」——
它正是那条配对的**执行**：变的只是标题那一面的**口味**（端正 → 书卷），
「有笔锋的衬线 vs 无笔锋的黑体」的对比关系原样保留。

## 五、结论：选哪个、为什么，以及那项连带决定

### 5.1 推荐

**标题族 = 霞鹜文楷 GB（`LXGW WenKai GB`）**，链上第三位保留 Noto Serif SC 作降级：

```css
--font-display: 'LXGW WenKai GB', 'Noto Serif SC Variable', 'Songti SC', serif;
```

四条理由，按用户点名的判据逐条对：

| 判据 | 文楷的表现 |
|---|---|
| **柔美度** | 楷体是「有笔锋的柔」——起笔顿、收笔有锋、笔画有粗细变化；不是手写体 / 艺术字，**不跳脱** |
| **与青瓷绿的协调性** | 青瓷绿是低彩度、冷调、偏「器物」的色；文楷笔画匀、墨色稳，在 `--glaze-mid` 浅底上**不发飘**。两者同向（温润）而非对冲 |
| **可读性** | 24px 以上极清楚；12–15px 会粘 ⇒ **只用于 display**（§四） |
| **可商用授权** | SIL OFL 1.1（LICENSE 文件正文，2022-2026 LXGW + Klee Project）✅ |

附带优点：**三档真字重**（§3.3 里唯一一款），要调重不用伪粗；**数字天然等宽**（§3.4）。

### 5.2 不选其他的理由（逐条，不是「试了不好看」）

- **霞鹜新晰黑**（2.3 MiB，最便宜）：它是**黑体**。换它等于放弃「黑体正文 + 有笔锋标题」的
  对比结构，页面会退回「一片黑体」——那正是用户说的「正文 Noto Sans SC 中性无风格」的放大版。
  **便宜，但不合用途。**
- **975 圆体 SC**（8.3 MiB）：柔美度够，但**圆的柔**与青瓷绿的「器物感」不同向
  （丸黑偏日系可爱），且**单字重**。跳脱风险高于文楷。
- **猫啃珠圆体**（2.7 MiB）：同上，且**授权无法举证**（§二）。
- **Source Serif 4**（2.1 MiB）：只有**拉丁字形**，中文回落还是宋体 ⇒ **解决不了中文标题的问题**。
- **HarmonyOS Sans / MiSans / vivo Sans**：授权闸就出局（§二）。

### 5.3 连带决定：display 字重 300 → 500（这一条要单独说清）

⚠️ 这一条**推翻了本笔初稿的结论**，把两次判断都记下来：

**初稿的判断（错）**：不改，理由是「文楷 300 已经比 Noto Serif 300 更实，『太细』换族就解决了，
而批级替换要动 9 份冻结稿」。

**实测把它推翻了**（同屏对照图：工具链 `美化/fontlab/shots/v5-weight-compare.png`）：

- 文楷 **300 / 400 / 500 三档的渲染差很小**（36px 下 400 与 500 几乎不可分）⇒ 改字重**不是为了更实**；
- 文楷 **300 确实比 Noto Serif 300 更实**（字面更大、笔画更饱满）⇒ 初稿那半句是对的。

**但真理由是另外两条，两条都指向「必须改」**：

1. **声明与渲染会不符**。若按 §七 只自托管 **500 一档**（10.8 MiB），链上就**没有 300**
   ⇒ 声明 `font-weight:300` 的元素**仍会用 500 的字形渲染**。要保住 300 就得多装一档
   （+11.4 MiB），而那 11.4 MiB 买到的正是上面实测「看不出差」的那点差别。
2. **批级自洽**。用户对商品详情页**点名**要 500（「标题保持衬线但不要 300 细体」），
   只改那一页 ⇒ **一页 500、九页 300**，这是一处**新的批级不一致**，比「动了冻结稿」更糟。

⇒ **10 份稿的 display 字重一起到 500**（16 处，`fontlab/unify-weight.mjs`，**净零行数**）。

⚠️ 关于「其余冻结」：用户的冻结条款指的是**不改其他页的设计决策**。换字体是**批级动作**
（改 4 第三步明说 `<link>` 指向新字体），它天然影响 10 份稿；而「声明 300 + 只装 500」
会让 9 页**实际渲染**变成 500 —— 那时候「冻结」在视觉上已经破了，只是破得不干不净。
把声明一起改到 500，是让**代码和呈现一致**，不是新增一笔设计改动。

## 六、替换做了什么（三步，与用户简报的三步一一对应）

| 用户简报 | 实际落地 |
|---|---|
| ① 搜 / 试候选、生成字体样张 | `美化/fontlab/specimen.html`（8 款对照）+ `weight-test.html`（字重对照）；本报告 §二–§五 |
| ② 给推荐 + 理由（柔美度 / 协调性 / 可读性 / 授权） | §5.1 的四条判据表 + §5.2 的逐条排除 |
| ③ 替换：tokens.css 指向新字体；设计稿 `<link>` 指向新字体；**保留 Noto 作 fallback** | `tokens.css` 的 `--font-display` 换值（链上保留 Noto Serif SC）；10 份稿各加 1 条 `<link>`（`ProductPage.html` 带详注，其余 9 份一行指过去） |

**没有动**：`--font`（正文）、`--font-mono`（等宽）、`--fs-*` / `--fw-*` / 间距 / 颜色。

## 七、落地成本与方案（落 Vue 时照这个做）

```
只装 500 一档：10.8 MiB / 491 片 woff2
```

- **是全字库口径** —— 不能只挑「看起来用得到」的分片（与 `noto.css` 同款规矩：
  中文按 Unicode 区间分片、按需加载，但**片必须齐**，缺片就是豆腐块）。
- 参照系：仓库现有 Noto + JetBrains = **10.1 MiB / 208 片** ⇒ 这一步是「**再加一倍**」的量级，
  不是用户担心的 +30MB。
- 若将来确实要 300 一档（比如某页要更轻的标题），**加装 11.4 MiB**；在此之前**别声明 300**
  —— 声明了也不会有 300 的字形（§5.3 第 1 条）。
- 顺带：`noto-serif-sc-*.woff2` 在落地后**可以删**（实测 **101 片 / 5.7 MiB**）——
  它退成降级链上的第二位，只在文楷加载失败时才用，不必全量自托管。
  （仓库现状拆分：noto-serif 101 片/5.7 MiB + noto-sans 101 片/4.3 MiB + jetbrains 6 片/0.1 MiB
  = 208 片 / 10.1 MiB。）
  ⚠️ 这一条**本笔不执行**（动 `src/assets/fonts/` 超出「只新增」的边界），列为落地时的一项。

---

## 八、一句话结论

**标题换霞鹜文楷 GB（SIL OFL 1.1、三档真字重、数字天然等宽），正文黑体不动；
display 字重随换族一起统一到 500；落地只装 500 一档 = 10.8 MiB / 491 片，
是仓库现有字体的 1.07 倍，不是 3 倍。**
