## 一、当前问题：量出来，不是看出来

用户原话：「个人页：整个页面只用『线条分割』→ 同质化严重（所有分区长得一样）。」

我**没有**用眼睛确认这条，而是建了 Q5 检查器 `measure-hierarchy.mjs` 把它数出来。
`[实测]` 判据：把每个分区级容器拿出来，看它给自己划界用的是**底色 / 横线 / 四边盒 / 留白**哪一种。

**`UserCenter-customer.html` 现状（5 个真分区）：**

| 分区 | 手法 | 底色实测 |
|---|---|---|
| 身份卡（声谷用户） | 留白 | `#f2f6f7` —— **≈白** |
| 数字行（stats） | **线** | — |
| 我的订单 | **线** | — |
| 我的收藏 | 底色 | `#e5e9ec`（这是 10 张商品图占位，不是分区底） |
| 设置 | 留白 | — |

**正面处理（底色/线/盒子）只有 3 / 5 个分区，其中 2 个是同一种「线」。真正用「面」划界的分区：0 个。**

### 三条具体病灶

1. **唯一的结构手段是 1px 发丝线。** 十份稿里分组、分区、表头、行分隔全部用同一条 `1px var(--line)` —— **同一种线用在四种不同的层级上**，等于没有层级。
2. **底色用了，但离白太近。** 身份卡确实有底色（`--zone`），可它 ΔE00/白 = **2.71**（详见《配色分析》第三节），眼睛读成白。**「加了底色」和「看得出是块底色」是两件事** —— 这条也是工具自己先判错、被用户反馈纠正过来的。
3. **所有区块等重。** 身份卡 152px、数字行 115px、订单 165px、收藏 662px、设置 371px —— 高度差有了，但**视觉重量没有差**：同样白底、同样发丝线、同样 24px 区块标题。

`[实测]` 对照：`ShoppingCart-customer` 有 3 个真分区，**正面处理只有 1 个**；`OrderCenter-merchant` 是 **只有一个手法（线×2）**。这不是个人页一页的问题，是这批稿共同的语法。

## 二、先回答用户要我权衡的那个矛盾：「极简」和「单调」的界限在哪

用户点名要我自己权衡。我的判断：

> **极简 = 手段少，但每种手段之间有明确的**强度差**。
> 单调 = 手段少，**且**手段之间没有强度差。
> 两者手段一样少，区别只在**差**。**

用数字说：一页里如果所有区块的白底都是 `#ffffff`、所有分隔线都是 `1px #dde2e5`，
那么无论加多少留白，区块之间 ΔE00 都是 0 —— **这就是单调**。
反之，区块之间只要存在**可测量的重量差**（底色 ΔE00 ≥ 4，或字号差 ≥ 1.5 档，或面积差 ≥ 3×），就是极简。

**⇒ 由此得到本笔的操作判据（可以拿去复核）：**

- 一个页面里，**分区之间**必须存在 ≥ 2 个不同的重量档；
- 同一档不允许连续出现 3 次以上（否则眼睛把它们读成一片）；
- 「留白」是**没有处理**，不算一个档（这一条是 Q5 检查器第七版修正的，见下）。

`[实测]` 为什么要有第三条：检查器最初把「留白」当成一种手法算进「种类」，
于是「线×2 + 留白×2」被报成「用了 2 种 ⇒ 有交替」——**而用户看到的恰恰是「全是线」**。
留白是**缺省**，不是手法；把它计进去只会虚增交替度。

## 三、改法：一套「四层划界语法」

判据 C 说的是方向（分组用线 / 分区用色块 / 同级用间距 / 重点用色）。我把它落成一套**可执行、可复核**的语法，四个层级各用一个手段，互不混用：

| 层级 | 手段 | 用什么 | 反例（现状） |
|---|---|---|---|
| **分区 ↔ 分区** | **面** 或 **大留白** | `--glaze-deep`（ΔE00 8.01）铺底；或 `--s8×1.4` 的间距 | 现状：分区之间也画线 ⇒ 线失去层级含义 |
| **分区内的分组** | **线** | `1px var(--line)`，且**只在这一层用** | 现状：表头、行、分区全用线 |
| **同级元素之间** | **间距** | `--s4`~`--s6` | 现状：订单四格之间既画竖线又挤在一起 |
| **重点（数字/选中/价格）** | **色** | `--brand-ink`（数字、选中）、`--accent`（价格） | 现状：数字全是黑，只有价格有色 |

**关键约束：同一种手段不跨层级用。** 线一旦被用来分隔分区，它就无法再表示「分组」——这是现状最大的结构问题。

## 四、逐页策略（判据 B），以及我对它的两处调整

判据 B 给的是一张「按元素密度决定用色量」的表。我**接受它的方向，调整两处**：

| 页面 | 判据 B 原文 | 我的执行 | 调整与理由 |
|---|---|---|---|
| **登录页** | 极简 —— 白底 + 品牌色只在按钮和 logo | **同意，但加一条**：左品牌区给一整块 `--glaze-deep` 面 | 「极简」不等于「全白」。块面不算「加色」，它给的是**版面重量**，不破坏极简。（ΔE00 8.01，读得出来） |
| **个人中心** | 有节奏 —— 身份卡浅色底 / 数字用色 / 列表用线 | **同意**，并把「浅色底」具体化 | 「浅色底」必须过 ΔE00 ≥ 4 那条线。`--zone`(2.71) 不合格，改用 `--glaze-deep`(8.01) |
| **商品详情** | 主区有色 / 次区白 / 功能色克制 | **同意**，微调 | 该页有彩 1.5%、青瓷绿 0.33%，主区（价格+领券）已经承担了色；**不额外加** |
| **搜索页** | 卡片 hover 青瓷绿 50 底 | **同意，且这条判断是对的** | `--brand-tint`(50) ΔE00 = **7.30** —— hover 会**真的被看见**，不是软绵绵的变化 |
| 订单中心 | 判据 B 未点名 | **保持**，只校准 | 密度高，色少不显；现状有彩 1.5% 但青瓷绿分布均衡，**不动结构** |

### 我把「统一」明确排除在目标之外

用户写「不要为『统一』硬加色」。我进一步：**十份稿的分区划界语法应当一致（同一套四层语法），但用色量必须按密度分档。** 语法统一、剂量不同 —— 这两件事不矛盾，且必须分开谈。

## 五、两个页面的具体改法

### `UserCenter-customer.html`（5 个分区，五块手法各不同）

用户自己给了一个方向（身份卡浅底 + 资产数字用色 + 订单色块 + 收藏卡片），我采纳并补足：

| 分区 | 现状 | 改成 | 为什么 |
|---|---|---|---|
| 身份条 | `--zone`（≈白）+ 右侧三项用竖线隔 | **`--glaze-deep` 整块面**（页面最大色块）+ 右侧三项改**间距**分隔，去竖线 | 全页唯一的「主视觉」，应当是唯一一块强面；竖线在这里多余 |
| 我的资产（积分/券/收藏/足迹） | 上下两条线 + 列间竖线 | **不画线**，纯**间距** + 数字 `36px 宋体` + 关键数字 `--brand-ink` | 判据 C「同级元素用间距」；数字是这一块的唯一重点，用色 |
| 我的订单 | 上下两条线 + 列间竖线 | **四块 `--zone` 浅底格**（格间 `--s2` 间距，无边框），hover → `--glaze-deep` | 与「资产」形成手法对比：同样是四格，一个靠间距、一个靠色块 |
| 我的收藏 / 足迹 | 图 + 名 + 价，无卡面 | 卡片 **hover 给 `--surface-2` 底**，去掉一切线 | 可点元素应当有可点反馈；`--surface-2` 对白 2.63 —— **这里够用**，因为 hover 是瞬时的、不承担分区 |
| 设置 | 字段线 + 按钮 | **保持线**（表单本来就该是线） | 这一块是页面上唯一「用线」的分区 —— 正好满足交替 |

**结果预期**：5 个分区 = 面（身份） / 间距+色（资产） / 色块（订单） / 卡片（收藏） / 线（设置）。
**没有任何两个相邻分区用同一种手法。**

### `UserCenter-merchant.html`

与客户版**逐字同构**（事实如此：两壳共用 `UserCenter.vue`），差异只在数据侧，因此改法完全一致，仅「经营数据」四格的数字语义不同。**不为「不一样」而做不一样的处理。**

## 六、验收：改完怎么证明真改了

三条都可以用脚本复核，不靠形容词：

1. **Q5** —— `measure-hierarchy.mjs`：正面处理从「线×2」变成 ≥ 3 种，且无相邻同手法。
2. **面积** —— `measure-area.mjs`：釉面/中性面从 14% 进到 10~20% 区间（现状 14% 里约 60% 是商品图占位，真实结构面接近 0）；青瓷绿从 0.43% 进到 1.5~3.5%。
3. **强度** —— `color-audit.mjs`：所有用作分区底的颜色，ΔE00/白 ≥ 4（不允许再用 `--zone` 单独分区）。

## 七、一句话结论

> 现状不是「线太多」，是**只有线**——同一条 1px 线同时承担了分区、分组、行分隔三种层级，
> 层级差被抹平成 0。
> 改法是给四个层级各配一种手段（面/线/间距/色），并且**让分区底色的 ΔE00 高于肉眼门槛**；
> 「极简」的底线不是「不许有色块」，而是**每一处手段之间必须量得出差**。

### 8.2 这一轮实测**发现并修掉**的两处（都是量出来的，不是看出来的）

1. **`.shops` 之前整体错位 16px**。客户稿的标题行是 `.h1row > .page-h + .edit`
   （`.h1row{margin-top:var(--s4)}` = 16px），商家 pane 把 `h1` 直接挂在 `.crumb` 之后
   ⇒ `.shops` 起始 y 差 16。**而商家 pane 的 `.h1row` 规则本来就在**（文件里`早已定义、无人消费`）
   —— 漏的是**消费点**，不是规则。补齐后归零。
2. **「编辑」缺失**。客户稿标题行右侧有 `.edit`（批量操作占位），商家 pane 没有。
   补齐时**不挂 `data-slot`**：该缺口已在客户稿那枚角标上登记过，在这里再挂一个会让
   「一处缺口」在账上变成两处（同 `.pledge` 的规矩）。

⚠️ 这两处**只有在量盒子时才暴露**：`grep` 查不出「少包了一层」，
1440 截图里 16px 的差也几乎看不出（除非并排）。这正是 §六 那三条验收脚本要补的盲区。

### 8.3 改 3 的验收：购入弹窗的列头与商品行

`.dlg` 宽 **760px**（`.dlg` 内左右内距各 48px ⇒ 内容宽 662）。列头与商品行**共用一份**

| 列 | 列头盒 | 商品行盒 | 判定 |
|---|---|---|---|
| 商品（跨列 1–2） | x=389 w=318 | thumb x=389 / nm x=469 | 左边缘重合 ✓ |
| 单价 | x=723 w=80 | unit x=723 w=80 | **完全相同** ✓ |
| 数量 | x=819 w=112 | qty x=819 w=112 | **完全相同** ✓ |

⚠️ 这里踩过一次坑并留了注释：`.li-head` 只有 **4** 个标签而商品行有 **5** 列，
后三个标签会整体左移一列 ⇒ 必须给「商品」那格 `grid-column:1/3` 把它并到前两列上。
**不做这一步时，「单价」列头会压到「商品」列上**——1440 截图能看出来，但 DOM 结构完全合法。

### 8.4 一处「只有出 1080 截图才看得见」的历史缺陷（已修）

改 2 之前，两稿的购物车在 **≤1120px 断点下长得完全不一样**：
客户稿隐列头 + 三行卡片重排，商家 pane 只把 7 列收紧。**1440 截图里两稿看不出任何问题。**
这一轮的修法是把商家 pane 的窄屏段**整段换成客户稿那套**（含 `::before` 伪元素补的
「单价 / 数量 / 小计」标签）。⇒ 出图必须**两个断点都出**，这不是形式。
