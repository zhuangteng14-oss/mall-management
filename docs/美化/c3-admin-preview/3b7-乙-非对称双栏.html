本版结构主张（LAYOUT 布局）：不改「总账 + 流」的阅读顺序，改的是组织方式——左 8 栏把状态机立起来（纵向桑基带 + 积压横条 + 预警）， 右 4 栏放辅图与实时流轨；耗时分布横向铺在下方，与纵向阶梯形成轴向对比；链路抽屉从右侧展开，7/5 两栏 + 全宽原始事件带。
业务灵魂落点：状态机与节点预警在 ② 左；SSE 流轨在 ② 右；耗时直方图在 ③ 上；超时积压与 Top 3 在 ③ 下；下钻抽屉在 ④。
代价：右栏窄，实时流每行只能显示「轨道点 + 单号 + 下一跳」，商品名与金额降级；抽屉覆盖右栏后，流轨暂时不可见。
结构判据与实测（点开看 · 业务灵魂落点 + taste-skill 四条命中台账）
一、业务灵魂放在哪里了
  • 状态机（② 左）：纵向桑基带编码累计到达（256 → 221 → 132 → 108），右侧横条编码当前积压（0 / 89 / 24 / 108），取消 35 作为唯一支线从支付段剥离。节点名后的「↘」是抽屉入口。
  • 超时预警（② 左 + ③ 下）：每个节点下常驻预警条；待发货 89 单全部超 24h（>7d 18、30d+ 13），待收货 24 单全部超 48h（且全部 >7d、>14d 17）；待付款阈值 60s，当前 0；完成/取消为终态。
  • 耗时直方图（③ 上）：三组横向桶，横轴 = 计数、纵轴 = 时间桶；付款双峰 0–5m/15–60m（78/77），发货集中 6–24h/1–3d（60/48），收货集中 1–3d/3–7d（44/41）。与 ② 左的纵向流向形成轴向对比。
  • 积压预警（③ 下）：两条全宽预警带，不是卡片；每带 = 大数 + 阈值 + 账龄分桶 + 最慢 Top 3 + 打开入口。待发货 30d+ 有 13 单（比 3–30d 的 11 单还多）；待收货最年轻的一单也已 >7d。
  • SSE 实时流（② 右）：ticker + 插入位 + 10 行轨道；每行 = 四点轨道（当前节点实心、下一跳虚线框）+ 单号 + 「→ 下一跳」。本拍 moves=0，插入位明确写「流入 0」；历史样例标为回放源，不冒充实时。
  • 下钻抽屉（④）：从右滑入，覆盖右栏；默认 sort=age_desc + 仅超时；左 7 = 最慢 Top 5，右 5 = 横向时间轴，底部全宽 = 原始事件带（0 条与原因）。
二、taste-skill 四条（逐条命中，不跑机器门禁）
  • 1. 相邻区块不得共用布局：① 读数带 = 三组横排；② 8/4 双栏（左纵向阶梯 + 右环/流）；③ 上部 3 栏横向直方图 + 下部 2 条全宽预警带；④ 7/5 抽屉 + 全宽原始事件带。3 对相邻，逐对形态不同。
  • 2. 不是卡片网格：全页 0 个等宽等高卡片（.kpi = 0）；阶梯是行、预警带是行、直方图是行，环图只有一个且是辅图；没有「三列图标卡」。
  • 3. 区块间距 > 内部间距：区块之间 28px；块内 12px；阶梯行距 8–9px；流轨行距 6px。分组靠边框与留白层级，不靠卡片。
  • 4. 一套统一的网格与边距：主区 padding 32px、12 栏栅格；② 的 8/4 = 2fr/1fr + 28px gap；③ 的 3 栏与 ④ 的 7/5 都取同一 12px 内间距；无独立边距体系。
三、stitch-design（只谈 layout / content / structure）
  • 无品牌色、圆角、阴影、过渡/动画；所有颜色只取灰阶变量。
  • 版本维度：本页是 LAYOUT 布局 —— 保留环图与「左主右辅」的阅读顺序，但把状态机立成纵向桑基带，把耗时分布改为横向桶，把抽屉改为右侧 7/5 展开。
  • 直方图的桶是结构：6/6/5 个桶的边界（0-5m、5-15m、15-60m、1-6h、6-24h、24h+ …）是后端口径，不是视觉分组；条的深浅不编码维度，只有长度编码计数。
四、frontend-design：大胆装置与反 AI 感
  • 一处大胆结构：左栏的纵向桑基带 + 积压阶梯。带宽编码累计到达、横条编码当前积压、预警条挂在每一级下方；同一个纵向轴把「漏斗」「库存」「预警」三种量串起来，替代「环图 + KPI 卡」。
  • 轴向对比：主视觉纵向（桑基带/阶梯），耗时分布横向（桶在纵轴、条在横轴），实时流是点状轨道；三种图不共用坐标系。
  • 反 AI 感：没有等宽卡片阵列、没有居中大标题 + 三列图标、没有圆角/阴影；右栏宽度只有左栏一半，信息密度按重要性分配，而不是平均分栏。
