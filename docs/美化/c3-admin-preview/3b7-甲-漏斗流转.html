本版结构主张（REIMAGINE 重构）：状态机不是折线图，而是一根「有体积的管道」——管道粗细是累计到达， 节点气泡是当前积压，预警牌挂在节点旁，取消是唯一支线；SSE 在途单按当前节点挂在轨道上，点节点或行进入链路抽屉。
业务灵魂落点：状态机与节点预警在 ②；耗时直方图在 ③（纵向分布，与横向管道成轴向对比）； 超时积压与 Top 3 在 ④（不等宽两舱）；实时流联动在 ⑤；下钻抽屉在 ⑥（积压订单 + 时间轴 + 原始事件，默认按停留时长倒序）。
代价：信息密度高，首屏同时看到管道、预警、流轨；最近订单不再是一张平表，不能按列排序（排序交给抽屉里的积压列表）。
结构判据与实测（点开看 · 业务灵魂落点 + taste-skill 四条命中台账）
一、业务灵魂放在哪里了
  • 状态机与预警（② 状态机装置）：管道粗细 = 累计到达（256 → 221 → 132 → 108）；节点气泡面积 = 当前积压（√ 缩放：0 / 89 / 24 / 108）；每个节点下方常驻一块预警牌，不是 tooltip。取消是独立支线（35，13.7%），不从主线假装流逝。
  • 超时预警（实测）：待付款 0（60s 阈值）；待发货 89 单全部超 24h，其中 24 单超 72h、18 单超 7d、13 单超 30d；待收货 24 单全部超 48h 且全部超 7d，其中 17 单超 14d、8 单超 30d；已完成/已取消为终态。
  • 耗时分布直方图（③）：三组纵向灰阶柱共用 0–78 的纵轴，横轴是时间桶：付款 6 桶（n=215）、发货 6 桶（n=126）、收货 5 桶（n=102）。桶的边界与计数都是结构的一部分，不是装饰：付款双峰 0–5m/15–60m，发货集中在 6–24h/1–3d，收货集中在 1–3d/3–7d。与 ② 的横向管道形成「横向流动 × 纵向分布」的轴向对比。
  • 超时积压（④）：待发货 89 / 待收货 24 两块预警舱按积压量做成不等宽（7:5）；每舱内是「阈值 + 停留时长分桶 + 最慢 Top 3」，不是一张只有总数的卡片。待发货的 30d+ 有 13 单（比 3–30d 的总和还多）；待收货最年轻的一单也已 >7d。
  • SSE 实时流（⑤ 流轨）：顶部 ticker 给出连接、拍号、流入/流出、本拍 moves；轨道线明确「SSE 流入 → 五个节点 → 终态出口」；在途单按当前节点挂在 5 条轨道上，每行有「当前节点 + 下一跳」箭头。窗口 = 最近 20 单，实测待发货 19 / 已取消 1 / 其余 0；不隐藏压测单占满窗口这一事实。
  • 下钻抽屉（⑥）：点任一节点/段、超时积压 Top 行或轨道行 → 底部抽屉；默认带参「状态 + sort=age_desc + 仅超时」，列表按停留时长倒序并标 Top 1–5；三栏 = 积压订单、订单时间轴（GOWW80602762 的真实时间戳）、原始事件（observed_event，空态写明 0 条与原因）。节点名后的「↘」是抽屉入口标记。
  • 实时感的边界：本拍 moves = 0（真实现状），所以 ticker 只放一条 observed_event 历史样例并明确标注「回放源，不是本拍实时」；不编造 from→to。
二、taste-skill 四条（逐条命中，不跑机器门禁）
  • 1. 相邻区块不得共用布局：① 读数带 = 三组横排；② 状态机 = 单张 SVG 管道；③ 直方图 = 三组纵向柱 + 桶轴；④ 超时积压 = 7:5 两舱（每舱 = 计数 + 横向年龄条 + Top 3）；⑤ 流轨 = ticker + 轨道线 + 5 栏票据轨道；⑥ 抽屉 = 顶栏 + sort 条 + 4/5/3 三栏。5 对相邻，逐对形态不同；没有两块共用同一套直接子元素结构。
  • 2. 不是卡片网格：全页 0 个等宽等高卡片（.kpi = 0）。五态是气泡 + 轨道栏 + 图例行，不是 5 张卡；票据是带下边线的行，不是盒子。
  • 3. 区块间距 > 内部间距：区块之间 28px（--gap-block）；块内 12px（--gap-in）；流轨的 ticker/轨道线/轨道板之间用 0 边框相接，内部票据行距 6px——分组靠外框而不是留白。
  • 4. 一套统一的网格与边距：主区 padding 32px、12 栏栅格；本页的所有块都落在同一 .px 内；抽屉三栏是 4/5/3，流轨五栏是等分 5 栏，间距都取 12px 的倍数。
三、stitch-design（只谈 layout / content / structure）
  • 本页没有品牌色、字号档、圆角、阴影、过渡或动画；颜色只取线框库灰阶。
  • 版本维度：本页是 REIMAGINE 重构 —— 不保留环形图，不保留五张 KPI 卡，把状态机、流轨、抽屉重新组织成一根管道 + 一条轨道。
  • 表达的是结构：谁大谁小（气泡/管道）、谁和谁相邻（预警牌贴节点）、从哪里进入哪里退出（SSE 入口/终态出口/取消支线）、点哪里下钻（↘）。
  • 直方图的桶是结构：6/6/5 个桶的边界（0-5m、5-15m、15-60m、1-6h、6-24h、24h+ …）是后端口径的一部分，不是视觉分组；柱高只编码计数，颜色不编码任何维度。
四、frontend-design：大胆装置与反 AI 感
  • 一处大胆结构：管道 + 气泡 + 支线的复合装置。横向管道编码累计到达，竖向气泡编码当前积压，预警牌贴着节点，取消从主管道剥离 —— 三种量共用一件装置，替代「圆环 + 卡片 + 折线」的常规仪表盘。
  • 轴向对比：主视觉是横向流动（管道 + 轨道），耗时分布是纵向柱（③）；一个回答「单子往哪走」，一个回答「在哪一段停得久」。两者不共用坐标系，避免所有图都长成同一种横条。
  • 反 AI 感：没有等宽卡片阵列、没有居中大标题 + 三列图标、没有圆角卡片 + 阴影；不对称（气泡大小、支线、5 栏轨道）由数据决定，不由模板决定。
