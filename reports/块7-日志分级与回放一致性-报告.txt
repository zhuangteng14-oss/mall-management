二、P0-1 日志等级与颜色语义重构
----------------------------------------------------
口径（唯一规则表在 EventBroadcaster#severityOf + 类注释）：
  PROTECT（紫）= 能解释数据变化原因的主动拦截，绝不是错误：
      入站限流 / 熔断翻转 / 库存不足（防超卖）/ 身份拒绝 / 敏感词拒收·打码 /
      重复提交拦截 / 出生闸拦下非法态 / 非法状态流转被拒
  WARN（黄）= 解决不了根本问题但系统能提示、能降级、已重试：
      L2 缓存降级与读取失败（回落 DB）/ 取锁异常（fail-open 直行）/
      释放锁异常（租约兜底）/ 锁等待超时 / MQ·通知重试中 / 审计·通知失败
  ERROR（红）= 数据链断裂 / 系统崩溃：
      result=error（SQL、未捕获异常、库存写库失败）/ DLQ /
      已落库后才观测到非法状态（强一致性被破坏）
  INFO = 成功路径与 miss/missing 这类「什么也没发生」。

指标与日志页口径：
  · 业务失败率 fail = error ÷ 事件数，**只数红色**；
  · warn 单列为「警告率」，protect 单列为「防护拦截率」；
  · 三口径并排展示但绝不相加，warn / protect 均不参与健康度。
  · 回放指标同样改为 error only，并新增 warn 折线（黄色虚线）。

五、P0-4 回放不再「偷梁换柱」
----------------------------------------------------
  · 状态页与指标页回放复用同一套高保真图表组件：
    折线图（LineChart）、环形图（DonutChart）、阶梯/漏斗、耗时直方图；
    给组件传 `:isReplay="true"`，图表角标显示「回放」，
    数据源绑定回放台账帧 `replaySession.metricTicks / stateChanges`，
    不再另画一套静态方块。
  · 回放时钟（rAF）逐帧推进；跨页用 hash 切页保活模块级会话；
    切页前暂停、到页再续播，回放不会在切页途中跑完。
  · 明确口径：回放指标由事件台账按日志时间 1 秒窗口推算，不是 HTTP 原始指标；
    QPS 是事件吞吐；延迟只统计带 DurationUs 的事件，无样本画断点而不是 0。
