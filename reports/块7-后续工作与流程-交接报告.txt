   现状：没有连接表、没有上限、没有心跳；spring.mvc.async.request-timeout=-1
   是 commit 10b 刻意关掉长连接超时的。
   前置裁决 A7：空闲超时做在 SSE 自己那层（SseStreamWriter「连续 N 拍写失败/无帧即收工」）
   还是改回正值的 async timeout（等于部分撤 10b）。两条都不能偷偷做。

② MQ 幂等 + DLQ 出口
   已有：topic exchange、主队列 durable + dead-letter、DLX/DLQ、prefetch 500、
   批大小 50、手工 ACK、应用层 3 次重试。
   缺：幂等键（observed_event 无唯一键）与 DLQ 的查看/重投/计数出口。
   前置裁决 A3：加 Seq 列 + UNIQUE(TraceId, Seq)（甲，新 DDL）还是弱键（乙）。
   注意：TraceId 可为 NULL（定时任务 / SSE 流线程），MySQL UNIQUE 不把两个 NULL
   当相等 ⇒ 那批事件天生去不了重，必须写进验收口径。
   前置裁决 A4：DLQ 出口是自建只读端点 / 走 RabbitMQ management / 只加指标。
   验收：同批次两条同键消息只落一行；DLQ 条数可见；毒消息有「明确不重投」路径。

③ 大表 LIMIT 默认 100
   前置裁决 A6：一刀切 100，还是只对时间序列表打默认、按业务键收窄的查询除外。
   会影响聊天记录、调度器扫描等既有行为（改的是用户看得见的行为）。
   验收：无上限的那批逐条给出「加了没有 / 加了多少 / 语义变没变」。

④ 数据脱敏
   真实靶子不是批文说的手机号/收货地址（本仓不存在），而是 user.email / user.address /
   merchant_application.ContactPhone / ShopAddress 四处出口。
   最危险的一处：/user/me 是本人资料编辑页的回填源；把掩码回给本人 ⇒ 页面把掩码
   当原值提交 ⇒ 数据被污染。必须区分「给本人」与「给第三方/管理端」，写接口要拒绝掩码值。
   前置裁决 A5：掩给谁？本人出口掩不掩？写接口怎么挡掩码值？
   验收：只对第三方/管理端生效；反向对照：本人提交一次资料，确认存下来的不是掩码。

⑤ 攻击模拟器更新（场景判据 + 开关面板接功能）

三、流程（这个仓怎么干活）
================================================================================

3.1 读文档的顺序
--------------------------------------------------------------------------------
· 新会话开场：agent.md（规则）→ docs/agent/README.md（文档地图）→
  当前任务的 context-pack → selection-status.md（§8 待办 + §9 新功能引出）。
· 做 C3 块：先 docs/agent/c3-blocks-index.md（8 块路线），再读该块 pack；
  不要整目录读 docs/。
· 块 7 相关：context-packs/c3-block-7-observe.md + c3-block-D-hardening.md；
  历史在 progress.md §7-B7 系列（只到 D2b，3a 要看 git log / 桌面报告 / evidence）。
· 技能/规范：docs/美化/看板规范.md；项目规则 agent.md §项目级规则。

3.2 决策分档（A / B / C）与三条硬线
--------------------------------------------------------------------------------
· A 必问：建表 / 改契约 / 删文件（三条硬线），或撞用户明令。
· B 自裁 + 报备：不落硬线，可自决，但要写进方案 / 收口。
· C 自决：落码时按方案走，不单独问。
· 先规划、后干活：不确定的改动先出方案，等人工确认；不要直接改代码。
· 数据库只允许追加：新增表/字段/索引无条件；新增 FK、改列类型有条件；
  禁止删表/删列/删索引/改旧行为。

3.3 证据优先（这个仓最核心的纪律）
--------------------------------------------------------------------------------
· 任何「修好了 / 通过 / 归零」都要有可复核证据：探针输出、截图、SQL 计数、
  actuator 读数、时间戳对照。
· 证据文件用 .txt（不要 .log：*.log 被 gitignore，git add 会整条失败）。
· 证据必须晚于最后一次代码编辑（提交前 stat 对比 mtime；早于代码 ⇒ 作废重跑）。
· 证据要读内容、不要只看 exit 0 / 绿色：校验器只验它查的那几件事，
  「OK」不等于没问题（checker-ok-means-only-what-it-checks）。
· 数字先定位证据：用户给的数字也要找出处；区分「可复核 / 叙述记录 / 推断」三档。
· 反面教材：假数据的形状要对着真帧；探针假定前提要先验证（例如「重复值」触发分支，
  不能拿不重复的数据跑）。
· 破坏性操作（清场 / 删行）要读回双重确认；Windows/GBK 下 curl 传中文会乱码。

3.4 探针与页面验证
--------------------------------------------------------------------------------
· 探针放 scripts/probes/；一次性的放 _work/（gitignored，不落桌面）。
· CDP 工具：docs/美化/_cdp.mjs（open / sleep / goto / evalJS / shot / send）。
· 页面探针在 docs/美化/ 下的 shot*.mjs / check-*.mjs 自带后端 mock（请求拦截），
  只需 dev server，不要让用户白起后端；但真实验收要用真后端 + 真前端，不用 mock。
· evalJS 是模板字符串：注释里不要写反引号或 ${，否则模板提前闭合，报错指向注释行。
· 登录口令从环境变量 PROBE_ADMIN_PWD 读（本地值 _work/admin-pass），不要硬编码。
· 视口高度会改变结论：同一 bug 1440×900 可能看不出、1440×800 必现；
  对照图必须 1:1（max-width:100% 会把 2× 裁图缩到 0.63×，正好抹平 1px 差）。
· 无头滚动条宽度不是恒为 0（经典 headless 0、--headless=new 15），每次实测。
· 圆形/树形/卡片等结构判据要逐子元素量，别只看首个；外壳类名可能与共用 CSS 撞车。

3.5 提交纪律
--------------------------------------------------------------------------------
· 小步提交、一笔一个目的；杂活单独一笔（先 chore 后功能）。
· git add 只列具体路径，不用 -A；git commit -F 文件，不用 heredoc；
  提交后 cat -n 抽查有无重复段。
· commit message 前缀：feat / fix / perf / refactor / test / docs / chore（带 scope）。
· 不 push / 不 merge / 不建 PR，除非用户明确要求（本仓批文：块 7 全部手验通过后
  由用户决定）。
· 明文口令会被 push 侧 [Credential Leakage] 拦；探针与文档都不许出现口令。
· 非用户手验的 agent 自测，标题必须写「agent 预跑记录（非用户手验）」。
· 未跟踪残留先归置，别混进功能 commit。

3.6 文档三层治理与引用纪律
--------------------------------------------------------------------------------
· 活文档：context-packs/、db-schema.md、api-contract.md —— 能不改就不改，
  只加新事实；块内不动，收口一次性重指。
· 账本：progress.md、slot-registry.md、tech-debt.md —— 块内一行不动，收口一次性追加。
· 档案：evidence/、archive/、progress.md 旧条目 —— 永不改，不追旧行号。
· 活文档引用写 #锚点（如 db-schema.md#db-16-1），不写行号；
  账本/代码/稿仍写「文件:行号」。
· 收口跑 bash scripts/doc-anchor-check.sh：
  当前实测 exit 0，悬空引用 0 条，死锚点 369 条（仅报告，不一定错）。
· 行号引用全仓互引：增删一行会让其后引用集体偏移；改注释也要净零行数。
  纯插入 hunk 的行映射：@@ -a,0 +c,d @@ 里旧行 a 不动、delta 从 a+1 起；
  算错会静默伪报 moved。
· refs-scan 产物的 before 用临时 worktree 取；只比「(引用者, token)」对；

3.9 常踩的坑（交接时先看这 10 条）
--------------------------------------------------------------------------------
1. 只看 job 颜色判断 A3（continue-on-error 让它系统性无信息量）。
2. 把「校验器 OK」当成「没问题」——它只查它查的那几件事。
3. 证据早于代码（mtime 必须晚于最后一次编辑）。
4. 数据源/模拟日常入口被重做挤掉（三页都必须保留「数据源」切换）。
5. 预览页覆盖 scoped 样式被压掉（scoped 编成 .kpi[data-v-…]，裸 .kpi 静默失效）。
6. 对照图不是 1:1（max-width:100% 把 2× 图缩小，正好抹平要看的差异）。
7. refs 报告落进 docs/，把旧行号抄成新 LOST。
8. 假数据形状不对真帧（把顶层键 remaining 塞进 fields，等于替错代码背书）。
9. 停 shell 不杀 Java 子进程（8088 仍被占）。
10. Windows/GBK 下 curl 传中文变乱码；python print 的 CRLF 让键名带 \r，
    破坏性操作要读回双重确认。
