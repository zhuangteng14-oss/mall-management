  ④ 本轮节奏是「草图 → 你确认 → 落地」，B **零后端改动**，今天就能在草图上把形状定下来。

【3. 选 B 的话，前端怎么合并排序】——**不能只按 timestamp**

  三键排序（稳定）：(ts, sourceRank, 源内游标)
    · ts        = 事件自带毫秒时间戳（同一台机器 ⇒ 跨源可比）
    · sourceRank= 同 ts 的固定优先级：事件 0 / 审计 1 / 演练 2（重复的东西总是事件更权威）
    · 源内游标  = events 的 seq / 演练的 recordId ⇒ 保证同一源两条不被交换（纯 ts 排序会抖）
  两条纪律（比排序规则更重要）：
    · **只做追加合并，不做全屏重排**：新行按 ts 只插进「尾部 N 行」内（N ≈ 30 行 ≈ 半屏），
      插入点之后**不重排** —— 否则滚动位置跳、③ 刚做好的平滑上移全废。
    · **迟到就丢，并计数**：ts 比窗口底还老的行直接丢弃，页面上写「迟到丢弃 k 条」。
      （③ 的窗口只有 1000 条，迟到行插进来会与已淘汰区域重叠。）
  每源一条读循环 + 各自重连退避（沿用既有 openResilientStream 语义）；断源 ⇒ 那一源的黄点变红，
  其余照常（= 选 B 的第 ③ 条理由）。

     点名的默认套路（大数字 + 小标签 + 渐变强调），本页不用。
  2. 结构装置编码信息（不许装饰性编号）——
     · 区号 ①②③④⑤⑥：**不是装饰**。它是「稿 / 方案 / 实现 / 验收」四份文档之间的共用坐标
       （你我的每条判据都在说「③ 的滚动条」「⑤ 的跳转」）。这四份文档里它就是真信息。
     · 前导符 ├─ │ └─ 编码 trace 的父子归属 ✓　· 折线/横条编码速率与占比 ✓
     · **不用** 01/02/03 那种装饰编号（那才是 AI 味）。
  3. 反 AI 感 —— 逐条对表：无奶油底 + 衬线开场、无近黑底 + 单酸色、无渐变、无阴影、
     无 ALL-CAPS 眉眼标签、无卡片 kit。⚠️ 两处**在册**的手法我确实在用，逐条给理由：
     · 小数据用等宽 —— 这是「控制台」这个题材的固有语言（docker logs / journalctl），
       不是套模板；taste-skill 也把「真界面片段」列为例外。
     · 用「·」连元信息 —— ③ 的行内就是「消息 · 对象 · 明细 · trace」的并列字段，

  4. 空状态是邀请（顺带查出的一笔）——「条件块未触发」「error 0 条」「⑤ 在模拟日常下恒空」
     三处都写了为什么空、怎么让它出现 ✓ 保留。
