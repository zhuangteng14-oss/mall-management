一、③ 事件流「等级」图标与 INFO 重叠（Bug 1）
────────────────────────────────────────────────────────────────────────────────
  你的判断是「图标和 INFO 之间缺 6-8px」，但实测发现根因不是缺 gap：
  · `.ic` 上本来就有 margin-right: 8px，图标盒子与 INFO 盒子的间距就是 8px；
  · 真正的问题是：`.ln` 为树形前缀做了悬挂缩进 `text-indent: -2ch`，
    而 `text-indent` **会被行内块子元素继承**。`.pre / .tm / .ic / .lv / .md`
    每个格子都是 inline-block（自带块容器），于是每格的首行文字都被再左移
    2ch ≈ 14.4px，盒子却没动。
  · 修复前实测：INFO 文本左缘 628.0px，格子左缘 642.4px —— 文字被拽到
    图标上，看起来就是「🗄INFO 挤在一起」。
  · 修复：五个格子统一 `line-height: 1; text-indent: 0` 收口。
    修复后实测：文本左 642.4 / 格左 642.4 / 差 0；图标右缘 634.4 →
    INFO 文字左缘 642.4 = 间距 8px，落在你要的 6-8px 里。
  · 顺带收益：树形前缀列、时间列的首字此前同样被左移，这次一并归位。

  证据图：docs/agent/evidence/c3-block7/3a3-mt-zoom-icon-info.png（6× 放大，
  图标 → 8px 空白 → INFO；类名蓝色）。

二、③ 事件流「类」列没高亮（Bug 2）
────────────────────────────────────────────────────────────────────────────────
  修复：`.md` 的 color 从 `var(--ink-2)`（一律中性灰）改成
  `var(--c, var(--ink-2))`。`--c` 由每一行的内联样式喂，值 = `kindColor(kind)`，
  与图标同一个来源 ⇒ 类名与图标必然同色；认不出的类回落中性灰。

  九类实测（图标色 === 类名色）：
    缓存 rgb(47,111,237)    蓝
    锁   rgb(255,106,0)     橙
    订单 rgb(34,197,94)     绿
    库存 rgb(245,158,11)    琥珀
    审计 rgb(168,85,247)    紫
    通知 rgb(6,182,212)     青
    敏感词 rgb(239,68,68)   红
    身份 rgb(132,204,22)    黄绿
    防护 rgb(236,72,153)    粉

  【额外修掉一个真缺陷 —— 探针读回时量出来的】
  行内严重度变量原来叫 `--c2`，而色板里 `--c2` 正是「锁」的颜色。CSS 自定义
  属性在同一个元素上解析 ⇒ 锁行的 `--c: var(--c2)` 吃到的是本行的**等级色**：
  INFO 青 #38bdf8 / WARN 橙 / ERROR 红 —— 同一个「锁」会随等级变色。
  修复：行内改名 `--sevc`，`.lv` 改用 `var(--sevc)`。修复后锁恒为
  rgb(255,106,0)，且在 info / warn / error 三档下同类同色。
  探针新增一条反向断言「同类不随等级变色」把这个失效模式封住（只钉
  「图标色 === 类名色」的话，两边一起错时是全绿的，挡不住这类撞名）。

三、滚动性能 —— 手写窗口化渲染（虚拟滚动）
────────────────────────────────────────────────────────────────────────────────
  先说现状：仓里没有 vue-virtual-scroller，也没有其他虚拟滚动依赖。
  按你的要求手写，没有引入新依赖。

  实现要点：
  · 数据侧不动：events 仍保留最近 1000 条（EVENT_CAP 不变）。
  · 渲染侧只铺「视口 + 上下各 5 行（OVERSCAN）」：
      - 行数 ≤ 200（VIRTUAL_MIN）时全量渲染 —— 小数据量窗口化没收益；
      - 行高可变（2 行截断 + 两档密度），所以没写死固定高：未测过的行
        用估值 36px，测过的行用 `.ln.scrollHeight` 实测回填（钳到
        2 × lineHeight），密度切换时清空重测；
      - 前缀和偏移表 + 二分查找定位首个可见行，窗口随 scrollTop 移动；
      - 上下各一个空白 `.vpad` `<li>` 撑住 scrollHeight。
  · 容器隔离（必做）：每行 `.ln` 已加 `contain: layout paint style`
    （浏览器 computed 归一化为 `content`，探针实测确认）。
  · 事件优化：滚动监听是 `@scroll.passive`（探针抓 addEventListener
    选项，确认 passive:true 真的传下去了）；rAF 合帧。
  · **没有** `scroll-behavior: smooth`，**没有** JS 劫持滚动做平滑；
    **没有**给整行加 `will-change: transform`；只在滚动容器上给
    `will-change: scroll-position`。

  1000 条实测（探针自接管 Fetch，喂一帧 1000 条事件）：
  · 数据侧「本页已收 1,000 条」；
  · DOM 实际只渲染：
      停在底部：19 行，idx 981–999，顶占位 35316px、底占位 0
      滚到顶部：20 行，idx 0–19，  顶占位 0、底占位 35295px
      滚到中段：25 行，idx 495–519，顶 17818px / 底 17295px
    scrollHeight 36015px、容器可视高 508px（1000 条总高的量级）。
  · 帧率：从 70% 处向上连续滚动 2 秒，rAF 帧间隔 122 帧：
      p50 16.7ms · p95 16.7ms · max 16.8ms · >33ms 0 帧（≈60fps）。
    说明：DevTools 的 Rendering → Frame Rendering Stats 是 UI 面板，
    CDP 没有对应指令可调；这里量的是同一时段、同一次向上滚动中的
    rAF 帧间隔分布，作为同一件事的代理量。
