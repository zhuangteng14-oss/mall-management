(A) 甲版预览（file://）vs 真页面（localhost:8080），同一个假流、同一套读取口径：

    内容高              2131 = 2131            相同
    .a-mp 宽            相同
    KPI 卡 宽×高        [271,271,271,271]×[94,94,94,94] = 真页面   相同
    画布[0] QPS         尺寸/ink/hash 全同       逐字节相同
    画布[1] 命中率      尺寸/ink/hash 全同       逐字节相同
    画布[2] 热力图      ink 160096 vs 160094 · hash 3441201332 vs 67601013   ← **唯一不等**
    画布[3] 柱状图      尺寸/ink/hash 全同       逐字节相同

    ⚠️ 唯一那块差在哪 —— 用 probe-b7a2b-heat-diff.mjs 从**原始 RGBA** 里定位（不靠眼）：
       255 个像素不同（占 0.090%），**全部**落在 x 495–590 / y 238–254，**最大通道差 12/255**。
       这个包围盒对应的是该图**底部 visualMap 的「0」「2」两个数字**；最大通道差只有 12/255
       ⇒ 是**抗锯齿**级差异，不是数据/几何位移。
       两侧各自 run-to-run 都可重复（真页面 4 块哈希两次完全一致，甲版亦然）⇒ 不是噪声。

    对照实验（用来把「字体加载路径」这一项单独拎出来）：**同一份**甲版预览，改走 http 供
       （127.0.0.1:8088）后，热力图那块差**变大**：4380 像素、**最大通道差 255/255**，
       差值成带分布（y 35–46 / 92–104 / 150–162 / 192–203 / 227–237，正是三行格子的位置）。
       ⇒ 差 255 的那种才是**结构性**位移。
       **机制推断（未做正反两向扰动复现，别当结论用）**：指向「首帧测量时字体到没到位」——
       热力图那块用了 `containLabel`，首帧 Label 测量依赖字体是否就绪，两次 render 的字体
       就绪时机不同 ⇒ 1px 级别位移 + 数字边缘抗锯齿不同。
       这 255 像素**不打算追**：量级是「数字边缘几个 alpha 值」，且不可控（不是代码能决定的）。

    ⚠️ 顺带推翻我自己先前的**猜**（原文写在预览页注释里，已改）：我曾猜 `file://` 下自托管
       woff2 会被 CORS 拒载（origin=null）⇒ 字形回退 ⇒ 画布必然不同。**实测推翻**：
       `file://` 下 `Noto` 与 `mono` 两份 `document.fonts.check` 都是 **true**。字体不掉。

六、本笔踩到的坑（五条，都记进代码注释或本报告了；前两条是「看错了/改了但没生效」类）
──────────────────────────────────────────
① **scoped 规则把差量静默压掉 —— 改了但没人看得见**（本笔最重要的一个错）
   第一版乙版差量里，「维度 3 去描边 / 卡底渐变 / 标签提亮」三条是**没生效**的，
   而且**看图看不出来**（`:→` 只是 1px 描边没了而已）。是 `probe-b7a2b-verify-deltas.mjs`
   把 16 条判据**读回来**才发现的：16 条里有 3 条两版**相同**，全是维度 3 的。
   原因：`KpiCard.vue` 的样式是 `<style scoped>`，编译成 `.kpi[data-v-89a6946e]`，比预览页里
   裸写的 `.kpi` **高一档优先级** ⇒ 被静默压掉（CSS 不报错、控制台不报错）。
   **落地含义（已写进 `b7a2b-pv-variant-b.css` 的头注）**：维度 3 必须是**改 KpiCard 自己的
   既有规则**，不是「在别处往下叠加」；预览页里为了模拟「改掉原规则」才给选择器挂了
   `html[data-theme="admin"]` 前缀做优先级 shim —— **落地时不要照抄那个前缀**。
   ⇒ 一般化：**「改了但没人看得见」这类翻车，只有把值读回来才抓得住**；肉眼看 1px 的差别不可靠。

② **注释里写 `/*` 会把块注释提前闭合**（我自己的注释把脚本写崩了）
   在 mk-preview 的注释里举例写了 `solid/*c*/red` ⇒ Node 直接 SyntaxError，报错行指向注释行。
   与之前记过的「探针 MEASURE 是模板字符串，注释里写反引号会提前闭合」是**同一个家族**的坑。

③ **产物会把 `文件:行号` token 抄进仓**（顺手治了）
   快照样式里带着本仓自带的注释，而本仓注释习惯写 `文件:行号` ⇒ 整份抄下来会在仓里留下
   **60 条按设计永不更新**的引用 token，`refs` 工具会把产物文件也当成引用来源 ⇒ 以后只会
   报成噪声。⇒ mk-preview 现在对 **CSS 与 DOM 都去注释**：
   · CSS 518719 → 397189 **字符**（落盘 397863 字节，含头注）
   · DOM 18824 → 13142 **字符** · 甲版 HTML 67908 → 57124 **字节**（含去注释 + 页顶注释改写）
     ⚠️ 这两处口径不同是因为它们来自不同代码路径（字符串 `.length` 是字符数、读文件的
        `Buffer.length` 是字节数），不是前后不一致。乙版 HTML 62077 字节。
   · **去注释后残留 token = 0 条**（实测，不是「应该没有」）
   · 判据：去注释前/后四块画布哈希**逐字节相同** ⇒ 去注释确实不参与渲染
   ⚠️ 剥离器是**认字符串**的，不是裸正则 —— `content: "/*"` 或 data URI 里出现 `/*` 时，
      裸正则会连真内容一起吃掉；并且用**一个空格**替换（CSS 里注释可充当词法分隔）。

④ **对照图被 CSS 缩到 0.63× —— 差点把交付图做成废图**（本笔第二个「差点看错」的坑）
   第一版 `b7a2b-compare.html` 里写的是 `img { max-width: 100% }`，而截图视口只有 1440
   ⇒ 2240 宽的 2× 裁切图被缩到 ~1408 ⇒ **1px 高光边 / symbolSize 6→4 / 虚线网格**这些
   「**就是要看的差**」正好被重采样抹平。
   当时现场：看乙版 QPS 那块，轴标签几乎看不见，我一度准备写「乙版把轴标签弄没了」——
   实际是**缩没了**（同一个证据链里，`out-b7a2b-shots.json` 的 ink 只降 2% 就已经说明
   标签没少，是我先看图后看数）。
   ⇒ 改成视口 2340（= 2240 + 标签列 44 + 间隙 8 + 两侧留白 32）+ `max-width: none`，
     并给探针加了**断言**：每张图必须按原尺寸渲染 + 全部加载成功，否则打印 ❌。
   ⚠️ 那条断言我第一版写成 `getBoundingClientRect().width !== naturalWidth`，它**含 1px 边框**
     ⇒ 2240 的图恒为 2242、**每跑必红**。已改用 `img.width`（内容盒布局宽）。
     **一个每次都响的哨兵等于没有哨兵** —— 加了断言也要跑一次看它绿。

⑤ 还没完的一条（纪律）：`DUMP=` 模式的原始 RGBA dump 每个 1.5MB，原先会落进**被跟踪**的
   `scripts/probes/` ⇒ 一笔提交凭空多 4.5MB 不可读字节，而它只是**中间物**。
   已改成落 `_work/3a2b/raw-dumps/`（.gitignore 内），并在探针里加了常量 + 注释说明。
