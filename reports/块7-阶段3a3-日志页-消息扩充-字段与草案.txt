零、先说三件「我核过、和你想的不一样」的事（不然下面的模板会写错）
════════════════════════════════════════════════════════════════════

1. **「谁」在真流里几乎没有**。九类事件里只有两类带主体：审计（`actor=`）和身份
   （`subject=`）。库存 / 订单 / 锁 / 缓存 / 通知 / 敏感词 / 防护 **七类没有**任何人。
   后端确实拿得到（`AuthSession` 的 `identity.userId()` 在拦截器上就有），但**没往事件里写**，
   MDC 里也只塞了 `traceId` 和 `batchId` 两个键。⇒ 想显示「用户 u-1001」**必须动后端**。

2. **「耗时」只有请求级的，没有事件级的**。链路记录（`RequestTrace`）里有 `ms`（= endMs − startMs），
   那是**整趟请求**的耗时；事件记录里**没有任何耗时字段**。
   顺带一个实证：锁的**等待时长后端其实算好了**（`lockMetrics.acquire(..., elapsed(startNanos))`），
   但它**只进了计时器，没进事件记录** —— `MallLockEvent` 那个 record 里就没有这个字段。

3. **「剩余 99」这类余量，真数据里没有**。`StockEvent` 只有 `skuCode / qty / result`，
   没有「扣完还剩多少」。演示源里那句「剩余 99」是 `demo-stream.js` 自己编的日常样例，
   **真流拼不出来**。

⇒ 所以下面的模板里，凡是你要求但今天拿不到的字段，我一律**留空位 + 标出来**，不编。

一、后端字段清单（哪些可用 / 哪些缺）
════════════════════════════════════════════════════════════════════

【A. 帧里到底有什么 —— 两个数组，字段固定】

事件行（`events[]`，11 个字段，逐个都有出处）：
  seq · ts · kind · severity · title · detail · key · objectType · objectId · traceId · batchId
  （后端 `EventStreamService` 逐行 put；`ObservedEvent` record 是这 11 个的源头）

链路行（`traces[]`，8 个字段）：
  seq · traceId · method · path · status · startMs · endMs · ms
  （`TraceLog.RequestTrace`；`ms` 已是算好的差值）

⚠️ 两条边界（都会让字段变 null / 缺失，必须知道）：
  · `traceId` 在**非请求线程**上为 null（定时任务、SSE 流线程自己产生的事件）⇒ 那类事件
    **没有请求可挂**，也就没有「请求中文名」和「请求耗时」。
  · 链路环只有 **256 槽**（`TraceLog.CAPACITY = 256`，覆盖式），而事件窗口是 1000 条、
    ③ 只画最近 200 行 ⇒ 老事件可能**已经找不到自己的链路行**。
    另有 `/stream` 结尾的路径**刻意不记**（SSE 长连接），所以三个流的请求永远不会出现在 traces 里。

逐格的口径与出处（右列就是我实际看到的东西，不是推测）：

· **谁** ✅ 的两个：审计 = `actor=`（写审计时传的是 `actor.userId()`）；
  身份 = `subject=`（`IdentityGuard` 记的是被校验的 id / 用户名）。其余七类**到此为止**。
· **什么请求** △：事件自己不记路径。能拿到是因为 `event.traceId` → `traces[]` 里有 method+path。
  前提两条：那趟请求**已经结束**（链路行是结束时才写的）+ 链路行**还没被挤出 256 槽**。
  实测口径：请求进行中的那几百毫秒里，新事件是「还没有请求中文名」的状态。
· **动作** ✅：`title` 就是后端给的人话（「库存扣减」/「取锁超时（fail-open 直行）」/
  「状态流转 CREATED → PAID」…），`kind`+`detail` 里的 `action=` / `kind=` 是英文原名。
· **对象** ✅：九类的 `objectType` / `objectId` 取值逐类不同 ——
  缓存=缓存键、锁=业务键（订单号）、订单=订单号、库存=SKU、审计=对象类型+对象 id、
  通知=收件人、敏感词=**命中的词**、身份=**被校验的请求路径**、防护=**哪道闸**（rateLimit…）。
  ⚠️ 同一格在九类里**不是同一种东西** —— 所以中文说明词必须逐类给（前端 `OBJECT_FIELD_LABEL` 已有这张表）。
· **量** ✅ 只有库存：`detail` 里 `qty=`。
· **结果** ✅：`detail` 里 `result=`（hit/miss/ok/insufficient/timeout/blocked…）+ 帧里的 `severity`。
  ⚠️ **要解析 `detail`** —— 见 §五 要你裁的第 3 件。
· **业务上下文** ✅：订单 `order#`（订单号）、通知 `event=`（事件码）+ `to=`（收件人类型）、
  敏感词 `scene=评论` + `hit=命中个数/total=文本长度`、审计 `targetType`+`targetId`、
  防护 `scope=`、缓存 `cache=`（缓存区名）、锁 `lock=`（锁名）。
  身份的「业务上下文」只有请求路径，△ 是因为**路径已经占了对象那一格**。
· **trace** ✅：`traceId` 原值（前 8 位已够用，现有 UI 就是截 8 位）。
· **耗时** ❌ 事件级：**九个 record 里一个耗时字段都没有**。△ 请求级：`traces[].ms`。

【C. 本节结论 —— 要挂 TD 的三处（编号是提议，等你点头再落 `tech-debt.md`）】

TD-80（提议）**事件帧没有「主体」**：七类事件的记录里没有 actor / userId 字段。
  补点已经存在：拦截器上有 `AuthSession.identity.userId()`；MDC 里现在只有 traceId/batchId 两个键。
  要落的话是「MDC 多一个键 + 九个 record + 台账列 + 帧」四处同改。
TD-81（提议）**没有事件级耗时**，且**锁等待时长已经算好却没进记录**
  （`MallLockEvent` 无此字段，值只进了计时器）—— 前者要新埋点，后者只是**把已算好的值带出来**。
TD-82（提议）**`detail` 是自由文本**（`kind=deduct sku=… qty=… result=… src=stock#128`），
  前端要拼自然流就得正则解析它。替代方案是后端把 detail 里的键抽成结构化字段。

二、每类拼接模板（草案）
════════════════════════════════════════════════════════════════════

【句子语法】`{动作短语(title)} {自然流从句}（{业务上下文} · trace {号} · 请求耗时 {ms}ms）`
  · 打头用后端 `title`（它本来就是人话），**不重写一遍动作**；
  · 中段用自然流从句（「在下单请求中扣减 …」），**不用 · 分隔的 key-value**；
  · 尾巴括号里是**键亮值灰**的三件套，可点的加下划线（见 §四）；
  · 超行宽自然折行（2 行上限、续行 2-3 字符缩进）—— 上一轮已落地，本轮不动。

【档位怎么体现】你定的档是**每类一个下限**，所以模板按类分派即可：
  档5（写操作 / 有业务后果）：库存 · 订单（状态流转 + 订单创建）· 锁 · 敏感词
  档4（只读但涉业务）：审计 · 通知
  档3（系统级 / 高频无害）：缓存 · 身份 · 防护
  ⚠️ 同一类里的子事件字段本来就不同（比如缓存有 transition 这种「可用性翻转」），
     模板按**子类型**再分一次，缺的槽位**跳过**，不写「-」也不写占位符。

【逐类模板】`{❌ = 今天拿不到，本轮不写}`　`{△ = 有前提}`

① 库存（档5，`stock` · kind=deduct/release）
   `库存扣减 {谁❌} 在下单请求中△扣减 {SKU} 库存 {qty} 件 {剩余❌}（trace {t} · 请求耗时 {ms}ms）`
   不扣成时：`库存不足（未扣，防超卖命中） {SKU} 请求 {qty} 件（trace …）` ← title 自己已经把话说完了
   落成示例（今天真能拼出来的最长形态）：
     `库存扣减 在下单请求中扣减 SKU_GD-101-9552 库存 1 件（trace 7f3a · 请求耗时 8ms）`

② 订单 · 状态流转（档5，`order` · kind=transition）
   `状态流转 {前态中文} → {后态中文} 订单 {订单号}（动作 {动作中文} · trace {t} · 请求耗时 {ms}ms）`
   ⚠️ 前后态有现成的中文表（`labels/order-labels.js` 的 `ORDER_STATE_LABEL`，
      8 个枚举名 + 非法态都在），动作表 `ORDER_ACTION_LABEL`（create/pay/deliver/receive）。
      **不用现编**。非法态那两条（出生闸拦下 / 观测到非法状态）走同一模板，前态就是「非法态·…」。
   落成示例：
     `状态流转 待付款 → 已付款（待发货） 订单 RZN123（动作 付款 · trace 7f3a · 请求耗时 12ms）`

③ 订单 · 订单创建（档5，`order` · action=create）
   `订单创建 订单 {订单号} 待付款（下单请求 · trace {t} · 请求耗时 {ms}ms）`
   ⚠️ **商品与金额今天拿不到**（事件里没有这两个字段，订单号之后的后端没往事件里写）
      ⇒ 你表里「商品 + 金额」两项**只能挂 TD 或砍掉**。

④ 锁（档5，`lock` · kind=acquire/hold）
   `取锁成功 {锁名中文} 锁 业务键 {订单号} {等待时长❌}（在下单请求中△ · trace {t} · 请求耗时 {ms}ms）`
   超时那条：`取锁超时（fail-open 直行） …`（title 已说明后果）
   ⚠️ 锁名有 5 个有界取值：order-add / order-pay / order-receive / order-delivery / friend-add
      ⇒ 建议登记成中文（下单锁 / 付款锁 / 收货锁 / 发货锁 / 加好友锁），与接口中文名同一张表。
   ⚠️ 锁事件的 `objectId` **就是业务键（订单号）**，不是锁名 ⇒ 对象格显示「订单号」，
      锁名要从 `detail` 的 `lock=` 里取。

⑤ 敏感词（档5，`sensitive`）
   `敏感词拒收 评论场景命中 {命中个数} 个词（词：{words} · trace {t} · 请求耗时 {ms}ms）`
   打码那条：`敏感词打码 …`
   ⚠️ `hit/total` 里的 **total 是文本长度、不是词数**（后端传的是 `text.length()`）
      ⇒ 模板写「命中 N 个词 / 文本 M 字」，**不能写「N/M 个词」**（那是误读）。
   ⚠️ scene 今天只有一个值 `评论`（后端字面量已经是中文）。

⑥ 审计（档4，`audit`）
   `审计写入 {对象类型中文} #{对象 id}（{actor} · 动作 {action} · trace {t} · 请求耗时 {ms}ms）`
   ⚠️ `action` 有 **45 条**现成中文表（`labels/audit-labels.js` 的 `AUDIT_ACTION_LABEL`）
      ⇒ 「动作」这一格也现成，不用编。

⑦ 通知（档4，`notify`）
   `通知发送 收件人 {toType} {收件人 id}（事件「{event 中文}」· trace {t} · 请求耗时 {ms}ms）`
   ⚠️ 事件码有现成中文表（`src/config/notify-events.js` 的 `EVENT_LABELS`，覆盖后端
      `NotificationEvents` 的常量）；`toType` 目前只有 user / merchant / admin 三个值，
      建议一并登记中文（用户 / 商家 / 管理端）。
   失败那条：`通知发送失败 … reason=…`

⑧ 缓存（档3，`cache`）
   `缓存命中（L1） {缓存区中文} {缓存键}（在下单请求中△ · trace {t} · 请求耗时 {ms}ms）`
   ⚠️ 缓存区名今天有 **8 个**有界取值（goodstype / goodsPrice / goodsHome / goodsCodes /
      goodsByMerchant / userPublic / friendList / friendRequests，全部来自各 `@Cacheable(cacheNames=…)`）
      ⇒ 建议登记中文（商品类目缓存 / 商品价格缓存 / 首页商品缓存 / 商品编码缓存 /
      商家商品缓存 / 用户公开资料缓存 / 好友列表缓存 / 好友申请缓存）。
      ⚠️ 缓存是档3，**高频**（实测占 ③ 窗口 76%）⇒ 串长必须压得住：缓存键本身就很长
      （`goodsHome::商家::商品`），**建议这一类的尾巴括号只留 trace、不留请求耗时**或整段省略，
      否则整屏全是折行。**这一条要你拍**（见 §五 第 5 件）。

⑨ 身份（档3，`identity`）
   `身份放行 校验 {请求路径}（{subject} · trace {t} · 请求耗时 {ms}ms）`
   ⚠️ 对象的那个值**本身就是请求路径**（后端把 path 当 objectId 用）⇒ 这一类的对象格写中文名会比
      写原值更可读（「校验 改商品」而不是「校验 /goods/goodsUp」）。**这一条也要你拍。**

⑩ 防护（档3，`protection`）
   `入站限流拦下 闸 {限流} 范围 {scope}（trace {t} · 请求耗时 {ms}ms）`
   ⚠️ 防护没有业务键（对象格装的是「哪道闸」）；「谁被拦了」要看同拍的 429/503。
   ⚠️ 熔断那条可能**没有任何业务请求在跑**（半开由 Resilience4j 自己的线程推）⇒ 那时
      traceId 是 null，模板要**整段跳过括号**，不能留一个空括号。

【演示源（「模拟日常」）会短一截 —— 这是数据源本身的差别，不是渲染退化】
  `demo-stream.js` 造的帧里 `detail` 只有「{类} · 模拟日常」，`traces` 恒为 `[]`（刻意不造链路）
  ⇒ 演示模式下：请求中文名、请求耗时、档5 的上下文**都没有**，句子退化成
  `库存扣减 库存扣减 SKU_xxx` 这种「只剩 title + 对象」的短句。
  **不补假数据**（那会让演示模式看起来比真流还真）。
