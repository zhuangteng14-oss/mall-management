二、为什么是现在做（本笔的定位）
--------------------------------------------------------------------------------
用户的下一步序里，3a.2b 要出「指标页甲/乙两版」——乙版**不是第二套设计语言**，
是**同一套色板的更高级呈现**。「两版之差」必须有且只有一个落点，那个落点就是这份
主题文件。所以本笔先做的是**切分「谁管什么」**：

    图组件     只管 数据 → option、本图特有参数（grid 留白 / 轴 min-max-formatter /
               柱子圆角方向这类**这张图才有**的东西）
    chartTokens 只管 从 CSS token 取值、拼参数
    theme.js   只管 **整站一个样**的键（轴、网格线、tooltip、色板映射、字体、动效）

三条约束已写进 theme.js 头注（防后人误改，也是 3a.2b 出手前必须知道的）：
  ① 合并序 = **option > 主题 > ECharts 内置默认** ⇒ 主题**只在 option 没写到的键上
     生效**。想让主题管某键，option 里就不能再写它。
  ② **主题不能声明组件** —— legend / tooltip / grid / 轴**必须出现在 option 里**
     （主题里写这些是 ECharts 的静默 no-op，踩上会以为「改了没反应」）。
  ③ 别把**图特有的参数**搬进主题（grid 留白、轴的 min/max/formatter、柱子圆角方向）。

三、验证：逐字节等价实测（不是「看着一样」）
--------------------------------------------------------------------------------
探针 scripts/probes/probe-b7a2-echarts-theme.mjs，口径：

  · **自起一台 8088 真 HTTP 服务**（不是 Fetch 拦截伪造）：/metrics/stream 逐帧
    `res.write('data: <frame>\n\n')` 每 400ms 一帧，**从不 res.end()**。
    ⚠️ 为什么必须「流不关」：页面的 openMetricsStream 带自动重连（onEnd → onLost
    → 重连），一次性喂完的假响应会让页面**每 ~500ms 重连并再叠一遍数据** ⇒
    画布永远在变、稳定态取不到。本笔踩过这个坑（30 轮不收敛），已记进探针头注。
  · headless Edge 打开入口页，页内对**每块画布**算 FNV-1a 像素校验和 + ink
    （不透明像素数），并逐图 dump **合并后**的 option（含 series dataHash/dataLen）。
  · 收敛判据：轮询到**连续两次取样逐字节相同**才算收敛（12 轮内不收敛即判失败）。
  · 入口两个各跑一遍：ENTRY 环境变量选 admin.html（暗色，`<html data-theme="admin">`）
    或 index.html（浅色）。两套 token 同名不同值 ⇒ 必须各跑。

结果：
  · **两入口 × 4 块画布 = 8 块，改前 vs 改后 6 块逐字节相同**。
  · 同树两跑的**自身可重复性**也验了：四块画布哈希两次完全一致
    （不先证明「同一棵树测得稳」，跨树比较无意义）。
  · 剩下 2 块（两个入口各一块，**都是同一张柱状图**、同一个机制）见 §四。

四、有意保留的观感变化（1 处，机制已钉死）
--------------------------------------------------------------------------------
**指标页柱状图的 y 轴刻度：从「一个数字都没有」变成正常数字。**

机制：改前 `valueAxis(t, { formatter: props.valueFormatter })` 在
`valueFormatter` 为 **undefined** 时也**无条件写** `formatter: undefined`；
ECharts 5.6 把这个键归一成**空串模板** ⇒ 值轴刻度全部渲染为空。

证据链（三步，缺一不可）：
  ① 给**改前那棵树**补同一个探针出口 → dump 出 `yAxis[0].axisLabel.formatter === ""`；
  ② **正向复现**：在改后的树上把该键**写回空串** ⇒ 柱状图画布哈希
     **逐字节回到改前的 189838597**；
  ③ 对齐设计稿：丁稿里**没写 formatter 的轴本来就是默认数字档**
     （`丁-运营蓝.html:555` 只给 color）⇒ 稿的意图不是「空刻度」。
  ⇒ 保留修复，不为了「像素全等」把这个 bug 写回主题。

⚠️ 中途我误判过一次根因（先假设 formatter:undefined 是元凶，被扰动实验**证伪**
——该键在别的图上 no-op）。改成「补探针出口 + 逐键 dump」才看到 `formatter: ""`，
再用正向复现定案。记在这里，因为「猜机制」和「钉机制」的差别就是这三步。

受影响面（同因，此前值轴刻度都是空的，共 5 处调用点）：
  MetricsPanel:125 / ModerationPage:204 / ModerationPage:452 /
  admin/StatsPage:155 / merchant/StatsPage:114 —— 都是不传 value-formatter 的柱状图。

  调用点各跑一次（可并入 3a.2b 的实测清单）。
